# MascotForge

Create a mascot, choose the least expensive workflow, export it, and connect its states to the project.

## Set up MascotForge

1. Start the server from the repository:

   ```bash
   python -m uvicorn backend.main:app --port 8766 --env-file .env
   ```

2. Set `MASCOTFORGE_URL`. It defaults to `http://localhost:8766`.
3. For the studio, paste the keys into Settings. For the CLI or MCP server, set `MASCOTFORGE_FAL_KEY` and, when needed, `MASCOTFORGE_OPENROUTER_KEY` in the agent process.
4. List the available options and estimates:

   ```bash
   python -m mascotforge styles
   ```

   MCP equivalent: `mascotforge_styles`.

The CLI output, API error messages, and studio UI are still in French. Translate those messages for the user instead of treating them as unexpected behavior.

## Interview the user before writing a prompt

Never invent the character prompt or state prompts on your own. Before you
generate anything, interview the user until you can write every prompt without
guessing. If the `interrogatoire` skill from
[superSkill](https://github.com/TokDar2410621/superSkill) is available
(`superskill:interrogatoire` in Claude Code), use it to structure the
questions. Otherwise, use the method below. You may tell the user that they can
install superSkill by running
`claude plugin marketplace add TokDar2410621/superSkill`, followed by
`claude plugin install superskill@superskill`, or by running
`npx skills@latest add TokDar2410621/superSkill`. Never install it without their
permission.

### Method

- Before the first round, inspect the project, including its README, home page,
  and agent name, so you can offer specific answers. Find facts yourself. Ask
  the user only for decisions.
- Work in rounds. One round is one call to the harness's question tool
  (`AskUserQuestion` in Claude Code, `request_user_input` in Codex Plan mode,
  or `ask_user` in Gemini CLI), with no more than 4 questions and 2 to 4 options
  per question.
- Put the recommended answer first. End its label with `(Recommended)` and
  explain the reason in its description. Always allow a free-form response.
- Ask a question only after you know the answers it depends on. If a question
  depends on another question in the same round, wait until the next round.
- If no question tool is available, ask the round in plain text. Number the
  questions, place the recommendation under each one, and phrase each question
  so the user can answer `yes` to accept the recommendation.

### Rounds

1. **Context**: Determine where the mascot will appear (`AI agent`, `website`,
   or `both`); what the product does and who it serves; the personality (`calm
   and reassuring`, `playful`, `serious expert`, or `mischievous`); and the
   starting point (`existing image`, `image generated by the agent`, or `free
   code-based mascot`).
2. **Character**, when you need to generate the image: Ask for the species or
   object, dominant color, accessory, and style (`kawaii plush`, `smooth
   vinyl`, or `flat illustration`). Offer options that follow from the product
   and personality.
3. **States** (multiple choice): Start with the preset that matches the use case
   (`agent`: idle, thinking, talking, error; `site`: idle, clicked, sleeping).
   Then suggest states that help this project, such as `listening`, `working`,
   `done`, `happy`, or `waiting`. Remind the user of the per-state price from
   `mascotforge styles`. Allow no more than twelve states.
4. **Reaction for each state**, up to 4 states per round: Ask, "In the
   `thinking` state, what does `<name>` do?" Offer 3 specific reactions that fit
   the selected personality. Decide whether each state loops (`idle`,
   `thinking`, `talking`, `working`) or plays once (`error`, `done`, `clicked`).
   Ask about looping only when the answer is unclear.
5. **Summary**: Show the image prompt, followed by a table with the name, loop
   setting, and English prompt for each state, plus the total price. Generate
   nothing until the user approves the summary.

### Write a state prompt

- Write it in English, keep it under 300 characters, and use one main action.
- Describe the facial change first, including the eyes and mouth, then the body
  movement. Kling preserves the face from the source image when the prompt does
  not name a facial change.
- Use small, steady movements for a looping state. Use one clear gesture that
  returns to the starting pose for a one-time event.
- Do not add camera movement, scenery, text, or a new object such as a computer
  or cup. MascotForge already adds these restrictions to the negative prompt,
  and those elements break background removal.
  Only an accessory visible in the base image may move.
- Do not repeat constraints MascotForge already adds: the same character, a
  static camera, a return to the starting pose, and a green background.
- Use lowercase letters, numbers, and hyphens for the state name. Start with a
  letter and use no more than 32 characters. `look` is reserved. At least one
  state must loop.

Save the approved states in a JSON file:

```json
[
  {"name": "idle", "prompt": "calm face, slow blinking, gentle breathing sway", "loop": true},
  {"name": "thinking", "prompt": "eyes look up and to the side, small mouth pout, slow head tilt", "loop": true},
  {"name": "done", "prompt": "eyes close into happy arcs, big smile, proud little hop", "loop": false}
]
```

## Choose a workflow

### Free blob

Use a blob for a lightweight, customizable mascot.

```bash
python -m mascotforge code --engine blob --set shape=cloud --out ./mascot
```

MCP: `mascotforge_code(engine="blob", config={"shape":"cloud"}, out="./mascot")`.

### Free blob designed by the agent

Use this workflow for a silhouette that the eight built-in shapes do not cover,
such as horns, ears, a star, or a crooked bean. The spec contains JSON data
only. Run the check and preview again after every correction.

```bash
python -m mascotforge blob guide --out ./guide-blob.md
python -m mascotforge blob check ./blob.json
python -m mascotforge blob preview ./blob.json --out ./contact-sheet.png
python -m mascotforge blob export ./blob.json --out ./mascot
```

MCP: Call `mascotforge_blob_guide`, `mascotforge_blob_check`,
`mascotforge_blob_preview`, and `mascotforge_blob_export` in that order.

### Free 3D character from the gallery

Choose an existing Wobnimo character.

```bash
python -m mascotforge code --engine 3d --set character=volt --out ./mascot
```

MCP: `mascotforge_code(engine="3d", config={"character":"volt"}, out="./mascot")`.

### Free 3D character designed by the agent

Use this workflow when the agent can inspect the reference image. Do not run a paid model.

1. Read the guide and inspect the image.
2. Write the Wobnimo JSON spec.
3. Check the spec.
4. Generate the contact sheet, compare its front view with the image, and correct the spec.
5. Repeat the check and preview until the spec is accurate.
6. Export it.

```bash
python -m mascotforge spec guide --out ./guide-wobnimo.md
python -m mascotforge spec check ./character.json
python -m mascotforge spec preview ./character.json --out ./contact-sheet.png
python -m mascotforge spec export ./character.json --out ./mascot
```

MCP: Call `mascotforge_spec_guide`, `mascotforge_spec_check`, and
`mascotforge_spec_preview` in that order. Compare the rendered image, correct
the spec, then call `mascotforge_spec_export`.

### Base image generated by the agent

Use this workflow when the user has no image and the agent has access to an
image generation tool, such as a Hugging Face MCP tool like Z-Image Turbo or
another connected image tool. Use the result as input for video, `image3d`, or
a Wobnimo spec designed by the agent. This workflow replaces MascotForge's
Flux generation.

1. Write the prompt in English from the interview answers. Use three parts:
   - Framing, always the same:
     `Mascot character, full body, centered, facing the viewer, on a plain transparent background, no shadow, no ground, no text, no other objects. Character: `
     If the tool does not support transparency, replace the background with
     `on a solid pure bright green (#00FF00) chroma key background`.
   - Character: species or object, dominant color, and no more than one accessory.
   - Style: one of the blocks below, or the style the user requested.
2. Generate 3 or 4 variations, each with a different character or accessory.
3. Inspect every image. Reject images with a ground shadow, gradient or tinted
   background, cropped body, or text.
4. Show the variations and let the user choose.
5. Save the selected image as PNG, JPG, or WEBP in the project. Pass it to
   `--image` for video or `image3d`, or use it as the reference for the
   Wobnimo spec.

Style blocks:

| Style | Block to append |
|---|---|
| Kawaii plush | `chubby round plush creature, one soft bean-shaped body with no neck, short stubby arms and legs, short dense fuzzy felt fur with visible fiber texture, two small glossy black bead eyes set wide apart, soft pink blush cheeks, tiny gentle smile, kawaii collectible designer toy, soft 3D render, studio softbox lighting, subtle subsurface glow, clean silhouette` |
| Smooth vinyl | `smooth glossy vinyl designer toy, rounded chunky proportions, big head, simple face, soft 3D render, studio lighting, clean silhouette` |
| Flat illustration | `flat 2D vector illustration, thick clean outlines, limited palette of 3 colors, simple shapes, sticker style` |

Rules:

- Never use a green mascot on a green background. Background removal would
  erase parts of the character.
- For a furry character, ask for `short dense fur` and a `clean silhouette`.
  Long fur keeps a green fringe after background removal.
- Draw inspiration from a style, never from an existing branded character. Do
  not copy the character, its name, or its combination of shape and colors.
- Include only the character description in the prompt. Never include personal
  data or a confidential project name.
- If the image tool costs money, state the cost and get permission before
  generating anything.

### Paid image-to-3D

Get the estimate first without `--yes`:

```bash
python -m mascotforge image3d ./image.png --out ./mascot
```

After the user gives explicit permission, run:

```bash
python -m mascotforge image3d ./image.png --out ./mascot --yes
```

With MCP, call `mascotforge_image3d_start(image="./image.png",
user_confirmed=false)`, state the estimate, get permission, call it again with
`user_confirmed=true`, then use `mascotforge_status` and `mascotforge_export`.

### Paid video

Pass the states from the interview with `--states`. Without a states file,
`--usage` selects a preset (`agent`, `site`, `complet`).

Get the estimate first without `--yes`:

```bash
python -m mascotforge video --image ./image.png --states ./states.json --out ./mascot
```

After the user gives explicit permission, run:

```bash
python -m mascotforge video --image ./image.png --states ./states.json --out ./mascot --yes
```

With MCP, call `mascotforge_video_start(image="./image.png", states=[...],
user_confirmed=false)`, state the estimate, get permission, call it again with
`user_confirmed=true`, then use `mascotforge_status` and `mascotforge_export`.

## Follow the safety rules

- Never run `image3d`, `video`, or a paid MCP tool without explicit user
  permission after stating the estimate.
- Never put a key in a URL, log, displayed command, or project file.
- Pass keys only through Settings or the designated environment variables.

## Integrate the export

1. Copy the exported directory into the project.
2. Add the component and its script:

   ```html
   <mascot-avatar id="mascot" manifest="./mascot/manifest.json" label="My assistant"></mascot-avatar>
   <script src="./mascot/mascot.js"></script>
   ```

3. Connect the state to the agent lifecycle:

   ```js
   const mascot = document.querySelector("#mascot");
   mascot.play("thinking"); // while the agent is thinking
   mascot.play("talking");  // while the agent is responding
   mascot.play("error");    // when an action fails
   mascot.play("idle");     // while the agent is idle
   ```

Use only states listed in the manifest. The widget maps common aliases,
including `talking` and `speaking`.
